# 《米花大舞台》與通用角色腦：資料及工程紀錄邊界

本文件是 **Mi 專案的實際管理規則**，適用於提交、測試、工程日誌與原生角色腦整合。

## 各自的歸屬

- **Mi（本儲存庫）**：遊戲世界與存檔、原著角色的身分／性格／知識、劇情及事件排程、NPC 的私有與主觀記憶、角色動態、遊戲規則、專屬測試資料、長跑日誌、效能分析與驗收結果。米花工程問題及驗收證據以本專案的 Issue／PR 為正式紀錄。
- **wRITE（獨立通用庫）**：作品無關的感知、注意、信念、記憶、目標、決策、學習、通訊、World 狀態及交易驗證等通用演算法、介面、單元回歸與通用工程紀錄。上游不應內建米花角色卡、劇情、私人遊戲存檔、測試歷史或遊戲特有的參數。

## 跨專案修正

1. 在 Mi 重現問題、保留精確角色／世界測試和 CPU 效能證據；只把**一般化的缺陷與最小必要重現**回報上游。
2. 需要修改通用能力時，在 wRITE 修改通用演算法並用作品無關測試驗證。可以附上 Mi 問題的外部來源連結作為**追溯指標**；這不代表角色記憶、世界進度或個別工程日誌屬於 wRITE。
3. 上游 PR 完成後，由 Mi **固定確切提交**，執行遊戲核心、原生整合、三 NPC 長跑、重啟與回執隔離測試；通過後才併回 Mi `main`。
4. 不要把通用 wRITE 的範例測試人物當成米花原著 NPC 的行為驗收。Mi 的原著人物測試應保存在 Mi，並區分受控 selector 與真正自主決策。
5. 不因效能最佳化刪減角色記憶、跳過因果／版本核對，或從角色主觀視角取得未觀察到的 World 真相。

## 既有歷史的說明

wRITE 的少數既有 PR 文字曾引用米花的 CPU 測試，這是**來源註記混用**，尚無證據顯示角色存檔被提交到上游原始碼。保留已合併 PR 的技術稽核歷史；後續的詳細測試、效能與角色紀錄，集中在 [Mi Issue #14](https://github.com/day2561124-art/Mi/issues/14) 和本儲存庫文件，不再在通用角色腦擴寫米花專屬工程紀錄。

## Native 實際資料目錄與舊存檔保護（候選）

伺服器啟動前以可信任設定 `MI_WRITE_DATA_ROOT`（預設 `.beika-private/write-data`）指定米花獨立的 wRITE 資料目錄。透過上游 `WRITE_DATA_ROOT` 功能，使世界歷史、記憶、Agent Run 與交易紀錄離開共用程式庫的開發目錄。若已有角色腦索引，只複製索引中屬於米花的 session 與相應神經軌跡；驗證身分與檔案雜湊，衝突時拒絕覆蓋，保留舊資料。新功能仍需完成上游及米花雙重 CI，GitHub 提交不會自動搬動使用者主機資料。
