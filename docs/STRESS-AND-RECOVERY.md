# Rebuild 0.12 長時間背景模擬與故障復原驗收

## 範圍

米花 World 的伺服器端多角色實際提交（使用具正式 API 契約的決策替身）與獨立 Native 收件匣。
驗證不同 World 的時間、回合計數、角色輪替、回執內容及崩潰後補送。
不要將此壓力測試混淆為真實 LLM 的自主性評估；固定版 `wRITE` 的原生整合由另一組 CI 驗收。

## 指令

```sh
npm run check
BEIKA_STRESS_TICKS=400 npm run stress
npm run stress   # 預設 2,000 次 World 回合，磁碟同步較耗時
```

CI 執行 400 回合的有界版本，完整 2,000 回合由工程驗收獨立執行，不阻塞每次快速單元測試。

## 不變量

1. 四個世界的世界時間只能遞增，各世界之間不共享角色狀態或回執。
2. 原生回合身分與雜湊必須一致，每個已接受的行動結果恰有一筆獨立回執。
3. 回執送達後、米花標記前模擬崩潰，重送後 Native 收件匣不增加重複事件。
4. 同操作識別重試不額外推進世界，也不能重跑角色決策。
5. 決策失敗或對帳失敗不能阻塞其他 NPC，且角色輪替不得長期飢餓。
6. 世界 event log、角色回饋紀錄有界；未送達資料不被拋棄。
7. 重新建立 WorldStore 後，存檔版本、雜湊、時間、回執與最近的上下游紀錄可以重新核對。
8. 系統時間倒退不得讓存檔 `savedAt` 回溯，也不得把部分建立的存檔公開。

## 本次實際驗收

本地 Node 22，2,000 World 回合、4 世界、每世界 2,500 遊戲分鐘。實際產生
6,000 筆不同的 Native 測試決策／回執，注入 34 次角色腦故障與 104 次對帳中斷，
包含 44 次回執重送、30 次 WorldStore 重建、87 次重複操作。所有壓力斷言通過。

> 回執數代表**受控測試提供者**的行為，不代表真實模型 API 呼叫數。
> 真正的 OS 斷電／多進程併發寫入／跨裝置登入與雲端資料庫仍未驗證。
